# 命令:全量审计

## 目标

LLM 主导的语义巡查:跨页一致性、反链网络、表达简化、人机矛盾、陈旧检测。

## 触发词

- 「审计」「audit」「全量审计」

## 与「lint」的区别

| 维度 | lint | audit |
|------|------|-------|
| 执行者 | PowerShell 脚本(机械) | LLM 主导(语义) |
| 检测项 | wikilink、记号、frontmatter、status、strength、orphan、proof section 等结构性检查 | 跨页一致性、表达简化、人机矛盾、引用精确度等语义检查 |
| 输出 | markdown 报告(自动) | LLM 分析报告 + 修复建议 |
| 频率 | 每次 wiki 变更后 | 周期性(建议每月)+ 大事件后 |

## 工具路径

- 入口: `wiki/.lint-last.md`、`wiki/open-questions.md`、`wiki/log.md`(最近 5 条)
- 读取: `AGENTS.md`、`wiki/index.md` 与相关 wiki 页
- 写入: 审计报告 + `wiki/log.md` + `wiki/open-questions.md`

## 完成判据

- 5 大类巡检全部覆盖(跨页一致 / 反链 / 表达 / 矛盾 / 陈旧)
- 输出结构化报告(发现 + 影响页面 + 严重度 + 修复建议)
- 与用户确认每条发现的严重度与修复优先级
- 高优先级项纳入下次 lint 任务
- `wiki/log.md` 追加 `## [YYYY-MM-DD] audit | <审计标题>`,简述主要发现
- 新发现的矛盾记入 `wiki/open-questions.md`

## autonomy

**一次确认** — 审计前一句话请示用户(可指定巡检范围或全量)。

**强确认** — 涉及跨多页大幅改动须用户明示批准。

## 机械不变量(必执行,不可省)

- 审计过程不得修改 `raw/` 下任何文件
- 审计中若发现 lint 已能检测的问题(如 wikilink 断裂),应优先运行 lint 修复再继续审计
- 审计报告应在会话结束前输出完整版

## 巡检清单(5 大类)

### 1. 跨页一致性

- 同一对象在不同页的字面陈述是否一致?(如 PSF 公式、Schwartz 空间定义)
- 同一引用在不同页的 citekey 是否一致?
- strength 判定在不同页是否一致?

### 2. 反链网络健康度

- 是否有单方向引用?(A 引 B 但 B 不引 A)
- 是否有循环引用?(A → B → C → A)
- 是否有过度集中的引用?(某定理页被 10+ 页引用但其证明引理未被独立建页)

### 3. 表达简化

- 是否有冗长但信息密度低的段落?
- 是否有不必要的数学符号滥用?
- 是否有可被 wikilink 替代的内联表述?

### 4. 人机矛盾

- `wiki/open-questions.md` 中的 open 项是否有最新进展?
- 是否有与现有 `verified` 页内容冲突但未记录的矛盾?
- 是否有用户明示的偏好未被采纳?

### 5. 陈旧检测

- 是否有超过 90 天未更新的 verified 页?
- 是否有被新源取代但未标记 `superseded` 的页?
- 是否有长期未被引用的页(候选孤儿)?

## 与其他命令的关系

- **前置**: `lint`(清理机械问题)、`status`(了解整体状况)
- **后置**: `refactor`(执行重构建议)、`verify`(核验审计发现的主张)
